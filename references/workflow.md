# 作業の流れ

素材フォルダとざっくりした指示から、CapCut で開ける下書きを作るまで。

## 1. 素材を確かめる
- 各ファイルの尺・向き（縦/横）・音声の有無を `ffprobe` で調べる
- 使う所の候補を、数秒おきのコマ画像を見て決める（音声があれば文字起こしも使う）
- 映ってはいけない物（他人の顔・車のナンバー・画面の個人情報・社外秘）が無いか見る

## 2. 型を選ぶ
- `recipes/catalog.json` の一覧から合う型を選ぶ。選んだ型の `README.md` だけ読む
- 合う型が無ければ、共通ルール（telop.md・structure.md）だけで組む

## 3. 構成表を作って見せる
カットごとに「時間・元素材のどこ・見せたい物・テロップ・音」を表にして、依頼した人に確認してもらう。
ここで直すほうが、下書きを作ってから直すより早い。

## 4. 下書きを書く
- CapCut を終了していることを確かめる（safety.md）
- 構成表を spec の JSON にして `python3 lib/build.py spec.json` で組む。型に `build.py` があればそちらを使う
- 試すだけなら `--drafts <作業用フォルダ>` で CapCut の置き場の外に組める（CapCut 起動中でも可。ただし CapCut では開けない）

## 5. 検査する
- `build.py` が最後に capcut-cli の `lint` を流す
- 見出しテロップは「読む速さ」の警告が出やすい（日本語の初期基準が字幕向けのため）。見出しなら無視してよい。字幕なら直す

## 6. CapCut で見て確かめる
- 簡易プレビュー（capcut-cli の `render`）は拡大・テロップを反映しないので、見え方は CapCut の画面で確かめる
- 確かめる所: 冒頭・カットの切り替わり・テロップの出る瞬間・最後。拡大した素材の端が切れていないか、テロップが媒体の UI に隠れないか（platforms.md）
- AI が画面操作できる環境なら、CapCut で下書きを開き、再生位置を動かしてプレビューを拡大して自分で確かめてから報告する

## 7. 仕上げと書き出し
依頼した人が CapCut で微調整して書き出す。書き出しは「ファイル → エクスポート」、形式は mp4。
